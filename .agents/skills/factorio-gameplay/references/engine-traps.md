# Engine and API traps (verified facts)

Each item says what is true, how it fails, and the workaround. Provenance: **[live]** = reproduced against the managed server in this repo (Factorio 2.0.77, Space Age, quality enabled); **[ticket]** = recorded in closed Beads tickets; **[README]** = repository contract; **[memory]** = earlier sessions, re-verify before relying; **[INFERENCE]** = reasoned, not observed. Repository schemas and live state outrank this file.

## 1. Addressing and identity

- **`unitNumber` alone is not enough.** `inspect`, `transfer`, `repair`, `fuel`, `waitUntil` targets and most entity-addressed operations reject `{unitNumber}` with `prototype is not resolvable by unit number alone; pass entity too` (or `entity not found by unit number; pass entity too`). Send `{entity:"lab", unitNumber:"60"}`. [live]
- Resource tiles, trees, rocks and ground items have no unit number: address by exact position (`{entity:"iron-ore", position:{x:-114.5,y:-38.5}}`). [live]
- Exact engine names only. `wall` does not exist (`stone-wall` does). Technology names are not recipe names. Ask `prototype`, `itemRecipes`, `researchInsights`. [live]
- `recipe(input:{actor:{...}, recipe:"name"})` wraps the actor; `inventory(input:{player:"x"})` does not. Without an actor, `recipe(input:{recipe:"name"})` still works and defaults to the player force. Neither `inspect` nor `recipe`/`recipeInfo` needs an actor for world data. [live]
- `characters(detachedOnly:true)` is the default and **hides connected players' characters**; use `detachedOnly:false` or `status.players[].actor.character`. [README]
- `UnitNumber` is a string in GraphQL; keep it quoted.

## 2. Placement and building

- `placeMany`/`removeMany` error indices are off by one: a batch of N placements reports `cannot place entity` (or `actor lacks item`) at an index that belongs to the *previous* entry, sometimes for a tile that was actually placed. Repro: place 5 belts with one blocked tile -> the blocked tile is reported one index off and `placed` + `failed` still sum to N-1. Never retry from the error list alone; re-read the tiles with `nearby`/`probePlacement`. [live 2026-11-01, ticks 1500426-1513866]
- `mapArea` paints every cell covered by an entity **footprint** (a 3x3 machine fills nine cells) and the highest-priority entity wins a shared cell; further prototypes collapse into one `?` row, so read `legend` before interpreting letters. An older `serve` build showed a filled mall row as `..........`; rebuild before trusting that symptom. [README][live]
- `production` returns `items` and `fluids` (same `ProductionItem` shape) and `itemNames` trims both; a zero row means no flow in that window, not a missing item. `itemFlow` rates are **theoretical** and unreliable for chemical plants/refineries; compute from live recipe `energy` and machine `craftingSpeed`. `itemBalance` combines observed flow, stock and starved consumers in one call. [README][ticket-skill]
- Container `inspect` can return `inventories: {}` for a chest that is **not** empty (chest 964 read empty while holding 161 automation-science-pack). Confirm contents with `stock(input:{item, area})` before declaring a chest empty or a source missing. [live]
- **Direction encoding in this save: belts are inverted on y, and an inserter faces its PICKUP side.** Belt `direction` `8` moves items toward **+y** and `0` toward **-y** (`4`=+x, `12`=-x as documented). An inserter's `direction` is the side it faces, which is its **pickup** side, and the drop is the opposite tile: `0` pickup `-y` / drop `+y`, `4` pickup `+x` / drop `-x`, `8` pickup `+y` / drop `-y`, `12` pickup `-x` / drop `+x`. Engine proof (units 11740 dir 0, 10489 dir 8, 11737 dir 12, 11684 dir 4) is `inspect{tick pickupPosition dropPosition}`: the pickup sits on the direction side, the drop 1.2 tiles the other way. So a machine **north** of an inserter with a chest **south** of it drains machine->chest at `direction:0` and inserts into the machine at `direction:8` — asking for 8 and expecting machine->chest inverts the flow (ticket tfi). `setDirection` does work on inserters (after `setDirection 0` that chest filled with 800 sulfur while the entity read pickup north); a stale `inspect.logistics` pickup/drop is the mod cache (ticket 0d9) and needs a Factorio restart, and `direction`/`before` in the mutation result are the engine readback. [live 2026-11-01 ticks 1507030-1513866 u1211/u1623/u1692; re-verified live 2026-11-02 ticks 3056884-3080871] **A mining drill is the other way round:** its `direction` is the DROP side — `0` drops north (`-y`), `4` east (`+x`), `8` south (`+y`), `12` west (`-x`) — the same sense as belt travel, opposite the inserter. Confirmed live 2026-11-02 at tick 2919457 (drill `(217.5,-93.5)` dir 8 dropped on the ground at `(217.5,-91.652)`, south of itself) and tick 3672835 (Z2 coal row: u11569 dir 0 sits north of the belt, u11576 dir 8 south of it, both drop onto `y=-95.5`). Do not reuse the inserter table for drills; see `spatial-and-geometry.md` section 5.
- An **underground entrance only accepts a feed from directly behind it** (the tile opposite its facing); a perpendicular belt cannot feed a tunnel mouth (its input then reads as a natural end in `beltStretch`). Consequence: a tunnel built inside a one-tile-wide corridor between two foreign belt rows has no usable exit - route to where one side of the corridor is free. [live]
- Underground halves pair by facing side, not by call: set `undergroundType: INPUT` on the entrance and `OUTPUT` on the exit, and the engine pairs a half as soon as a facing half of the same tier exists — same batch or later call. Without the flags both halves become entrances and items dead-end. Prove pairing with `beltStretch` (tunnel collapses to one hop) or measured flow; `undergroundNeighbour` is always null on 2.0.77. [README][live]
- A direct `direction` write lands on **transport belts** in this build (`setDirection` returned `turns:0` with the readback changed, on an empty belt and on one carrying an item, live tick ~1.22M); rails are reported to ignore it. When the direct write is refused, `setDirection` falls back to walking the shorter way round in quarter-turn `rotate` steps (up to three), re-checks after every step, and fails with `remove it and re-place it` instead of acking a direction it never reached; a target that is not a multiple of 4 is rejected on that path. `turns:0` proves the direct write worked, `turns:1..3` proves the rotate fallback ran. Inserters, machines and pipes-to-ground take the write directly. [live][README][ticket tfi][replay tests]
- A placement fails while the acting character stands on the target tile (`cannot place entity at position`). Navigate ~3 tiles off, then place; use the response's snapped position afterwards. [memory]
- `probePlacement`/`worldPlacement`/`nearestPlacement` use the engine's **manual build check** (the rules a hand-placing player gets), so offshore pumps need water and pumpjacks need crude instead of passing on bare ground. They still answer per prototype and direction only; a prototype requirement can surface as blocked tiles with an **empty** `blockers` list, so read `terrain`/`tile` and use `nearestPlacement(requireResource, minResourceTiles)` for mining footprints. `probePlacement` samples tile centres only, so a 3x3 machine needs `worldPlacement`/`nearestPlacement` to prove the whole footprint. `probePlacement` additionally applies the plain-placement **occupancy** rule: a tile holding a real entity is blocked for **every** direction even when `can_place_entity` would accept it (a belt on a belt of another direction passes the engine check as a fast-replace), so it can disagree with `worldPlacement`/`nearestPlacement` on occupied tiles; resources, ghosts and item stacks do not block, so belts stay placeable over ore. [README][live]
- A **single-tile** `connectEntities` run has no route to derive a heading from; before the fix it placed a **north-facing** entity silently (Lua `build()` left `d=0` when `#steps==1`). The mutations now take `direction` (0/4/8/12): required when `from` and `to` resolve to the **same tile**, rejected for runs of two or more tiles, and refused before any Lua runs, so a bad call spends nothing. `connectionPlan` refuses single-tile routes outright. The mutation result's `entities[].direction` carries the engine heading each tile was created with (`0` is reported as 0, not null; underground halves also carry `undergroundType`), so no readback is needed (factorio-ai-player-of0); an older `serve` binary still returns null. Corollary for hand-built corners: lay a corner as a **two-tile run** (or pass `direction`) — never a one-tile run, and never rely on the old silent default. [live tick 989k; source fix]
- `placeBlueprint` places **entity ghosts**, consumes nothing, and only rotates in 90° steps: `direction` must be 0/4/8/12, anything else is rejected before RCON. The result reports `ghosts`, blueprint `entityCount` and `skipped`. `placeGhosts` does the same from explicit entity/tile entries at absolute positions; `buildGhosts` revives without robots but charges each ghost cost from the actor main inventory then an optional source inventory, refunding a refused revive and reporting `MATERIALS`, `COLLISION` or `ENGINE` per ghost. [README][live]
- `place` can commit the entity and then fail response decoding: `decode place response: json: cannot unmarshal string into Go struct field ActionResult.direction of type int`. `placeMany` is unaffected. The working tree now normalizes `DirectionString` names to engine ints (unit-tested `TestPlaceDecodesDirectionString`); an older `serve` binary still has the defect. Read back the entity by `unitNumber`/position before retrying. [live][source fix]
- `clearArea` deletes trees/rocks with no drops; `harvestArea` mines with drops. [README]
- `dropItem target:GROUND` refuses a tile with a belt/splitter/loader (the stack would be swallowed); use `BELT`. A ground drop is created with no force and belts disabled, so it is **never marked for deconstruction** (older builds did mark spilled stacks); the result reports `remaining`, `groundPositions` and `line`. [README][live]
- `mine` targets resources, trees, rocks and simple entities, which have no unit numbers: a `unitNumber`-only target is rejected, so pass `entity` + exact position. `beltTake` accepts any transport-belt tier and fails (after spilling the remainder near the character) when the inventory cannot take part of the removed items. [README][live]

### Engine/Lua traps proven this wave

- `LuaSurface.spill_item_stack{force=...}` **marks the spilled items for deconstruction**; omit `force` for items that must stay. The API's `dropItem` already passes no force for ground drops.
- `LuaEntity.neighbours` for a fresh underground belt is not a plain table that `pairs()` accepts. Iterate with `ipairs`/`pcall` and probe `n.valid`; never test `type(n)=="table"` (it raises or silently yields nothing).
- `find_entities_filtered{position=..., radius=...}` matches **entity centres** by distance, so a 0.01 circle at a rounded coordinate finds nothing. Scan an area and test `entity.bounding_box` for containment instead.
- Corpses (`type=corpse`: tree stumps from mining, remnants, biter corpses) use base-game mask `{layers={doodad=true}, colliding_with_tiles_only=true}`, so they never obstruct a build — `place`/`placeMany`/`probePlacement` all build over a stump. The occupancy rule that matches the engine is a mask intersection against `prototypes.entity[name].collision_mask.layers`, not a type list; testing the requested point instead of the whole tile also misses a neighbour whose box clips the tile. [live][ticket sth]
- `find_entities_filtered{collision_mask=...}` wants the bare layer dictionary (for example `{layers={...}}` values straight from `prototypes`), while `request_path` takes the `CollisionMask` wrapper; mixing them errors.
- `LuaEntityPrototype` raises on unknown keys; there is no `.prototype` field on an entity, and missing optional prototype fields must be read through `pcall`.
- Container `bar` is an index where the blocked area starts, so usable slots = `bar - 1`; the API writes `allowedSlots + 1` and reports both.
- A raw `LuaSignalID` read of an item signal has `type` nil/empty, so serialize item signals as `"item"` instead of trusting `icon.type`.
- `recipe.hidden` recycling recipes pollute naive recipe enumeration; filter `hidden` (and `parameter`) before presenting candidates.
- `mine` is **instant** (not timed), but needs reach in practice: a character reports targets ~5 tiles away as `outOfReach`; navigate to within ~1-2 tiles with `tolerance 1`. `harvestArea` inserts yields directly into the main inventory, so a following `pickupArea` finds nothing. [memory]
- Burner drills can spill one item on their output tile and stall (`waiting_for_space_in_destination`); `pickupArea` over the patch box clears it. [memory]
- Chests: `setContainerBar allowedSlots` is the number of USABLE slots (null = no limit, 0 = every slot blocked, and `transfer TO_ENTITY` then reports `moved:0`). The engine stores a bar index instead, so the mutation writes `allowedSlots+1` and reads report both `bar` (raw index, 0 = no limit) and `allowedSlots` (bar-1, null when unlimited). Live: wooden-chest 202 bar 2 -> allowedSlots 1. [live][ticket 095.6.2]
- Stack size and fuel value are now available: `prototype(name){ item{ stackSize fuelValue } }`. Verified: iron/copper/steel/pipe/processing-unit 100, LDS 50, rocket-fuel 20, coal/ore/stone 50, circuit/science pack 200, wood 100. Fuel values: coal 4 MJ, wood 2 MJ, solid-fuel 12 MJ, rocket-fuel 100 MJ. [live]

## 3. Actors, crafting, transfer

- Sandbox scenarios strip the player's character and leave a god controller (`controller_type 2`, no character); `player:`-addressed operations then fail ("player has no character"). `playerRestoreCharacter` fixes it, or use `characterSpawn`. [README][memory]
- A player whose controller is an unusual type can show `hasCharacter:true` but fail `player:` actors with "actor has no main inventory"; use `actor:{character:"<unit>"}`. [ticket-skill]
- A disconnected player's crafting queue does not advance; use a detached character. `craft.requested` counts crafts, not items (with `mode: UP_TO` it is the computed crafts still needed to reach the wanted total); `wait:true` returns when the **entire** queue drains. [README]
- `craft(wait:true)` is for bootstrap only; for anything repeated build an assembler.
- `craft` `count` is an increment by default (`mode: MORE`), so re-issuing a timed-out call duplicates the batch; use `mode: UP_TO` (count = wanted product total, queued crafts counted) to resume. Queued crafts take their ingredients only as each starts, so inventory alone over-reports spendable stock.
- `player { cheatMode }` / `playerInsight { cheatMode }` true means crafting is free and instant for that player: craft cost, timing and `craftableCount` are meaningless evidence. A detached character reports null.
- `transfer` moves between an actor and **entity** inventories only. Character -> player direct is impossible; stage through a wooden chest (2 wood): everyone deposits `TO_ENTITY`, the receiver withdraws `TO_ACTOR`. [memory]
- `transfer` and `fuel` need both `entity` and `unitNumber` on the target. `fuelMany`/`transferMany` reject duplicate targets and fill exactly `countPerTarget` or fail that target (no partial fill). [README]
- Quality: items default to `normal`; mutations take `quality` explicitly.
- `LuaEntity::set_recipe` is **assembling-machine only** in 2.0.77; a furnace ghost fails with `could not set recipe: Entity is not assembling-machine`, and furnaces choose their recipe from the item in their input. `setRecipe` therefore handles a furnace by moving one unit of the recipe's item ingredient (and `recipeQuality`) from the actor inventory into the furnace input and leaving it to be smelted, reporting it as `item`/`count`; it fails when the actor inventory has none or the furnace keeps a different recipe that can consume that item. Assemblers and chemical plants still need the machine idle and empty (`drain: ABORT|TO_ACTOR|SPILL`); `clearRecipe` refuses furnaces. [README][live]

## 4. Logistics, circuits, power

- Script-set requester slots fill to **`min`**, not `max`. `min:0,max:50` delivers nothing; set `min=max=N`. [memory][ticket-skill]
- `logisticNetworks.contents` can be negative while demand is unmet. Not stock. [ticket-skill]
- `stock` excludes wagons, vehicles, robots, roboports, turrets, linked chests, equipment/trash and fluids. [live schema]
- `electricNetworks.satisfaction` can be null. `powerConsumers.connectedToProducingNetwork:false` is a predicate on producing networks, not proof of no network. [live schema]
- Power poles join networks when wire distance <= min(reach_a, reach_b). Big (32) to medium (9) is only 9. [live]
- A circuit condition only inhibits when the inserter is physically wired. `enabled:false` is rejected for ordinary inserters. Counters mixing a chest's item signal with hand-HOLD signals drift. [ticket-skill]
- `circuitNetwork` now emits the uppercase `WireColor` at the Lua source (`RED`/`GREEN`), so the `normalizeGraphQL` colour rewrite is only a leftover safety net. The read also reports `connector` (default `circuit_<color>`, which on a combinator is its INPUT connector), `networkId` (equal ids mean one network) and `networkCircuitCount` (engine `connected_circuit_count`: circuits attached to the network, not this entity's wires). Pass `connector:"combinator_output_red"` to read the network a combinator drives. [ticket 095.6.6/095.6.14]

## 5. Reads that mislead

- `production` now returns `fluids` alongside `items` (same `ProductionItem` shape, same window); `itemNames` trims both. `itemFlow` rates are **theoretical** and unreliable for chemical plants/refineries (they reported 10-15). Compute from live recipe `energy` and machine `craftingSpeed`. Use `fluidSegments`/`fluidStock` for fluid truth. [README][ticket-skill]
- Full belt != throughput; measured 0/min can be a downstream sink that is full. [ticket]
- `beltStretch` snapshot mixture on a jammed belt is static stock, not contamination; confirm crossings with `beltStretchMeasure`. [ticket-skill]
- `belts` sees transport-belt only (no underground/splitter/loader lines); `worldLogistics` needs one type per call and rejects roboports.
- Older `serve` builds fail `prototype(name:"inserter")` (also `burner-inserter`, `long-handed-inserter`): `cannot unmarshal array into Go struct field EntityPrototype.entity.inserterDrop of type main.Position`. Factorio `Vector` is a two-element array; the working tree normalizes `inserterPickup`/`inserterDrop` to `Position` (unit-tested and real-engine integration). Until `serve` is rebuilt, use the geometry formulas in `spatial-and-geometry.md`. [live][source fix]
- Research: `researchInsights.prerequisites` is `[{name researched}]`, not strings. `researchTriggerJSON` marks trigger techs. [live]
- `mapArea` legend letters change per call. [live]
- A `waiting_for_space_in_destination` pumpjack usually has an isolated stub output pipe. [memory]
- `factoryBriefing` sections are read at different ticks; ghosts follow the scope (area when given, otherwise whole surface), stockouts need `watchItems`. [live]
- **Inserter endpoints go null while the inserter is idle.** Factorio only populates `pickup_target`/`drop_target` once the inserter has run, so an unpowered or never-fed inserter reads `pickup:null, drop:null` in `factoryGraph`, `inspect.logistics` and `adjacency` even with a chest on its drop tile (verified live 2026-11-01: inserters `940/943/946` reported null drops while iron-chests sat on those tiles; the drop appeared after the assemblers were fed). The working tree falls back to the entity under `pickup_position`/`drop_position`, and `factoryGraph` also scans inserters only one tile beyond the area instead of the whole surface. Until `serve` is rebuilt, decide dead vs idle from geometry (`inspect.dropPosition`/`pickupPosition` plus `nearby` on that tile), never from a null target: deleting inserters on a null drop is wrong. [live][source fix]

## 6. Server, navigation, notifications

- **`shutdown` does not save.** Always `save` first; do not stop the shared server at all in normal play. [README]
- First RCON Lua command on a fresh save can trigger the "Lua console commands will disable achievements" prompt; the retry proceeds and permanently disables achievements for that save. [README][memory]
- `scripts/server.sh start` defaults to `ai-player.zip` when `FACTORIO_SAVE` is unset; `just restart` can silently switch saves. Do not restart the shared server; see `multi-agent-and-operations.md`. [memory]
- Navigation: one job per character; a second start fails with the active job id in the message, and `navigationActive(actor)` recovers the id of the job the character is currently walking. `targetEntity` is the shared `EntityRefInput` (prototype name + position preferred; a unit number alone only for engine-lookup prototypes) resolved on the walker's surface, and `position` goals inside an entity are snapped out of collision. `NavigationJob` reports `tolerance`, `timeoutTicks`, `replans`, `waypointsRemaining`, `distanceRemaining`. Paused server cannot advance it; manual client input competes with scripted walking for a connected player; `targetCharacter` can fail `NO_PATH` when the target stands among belts/inserters, so navigate to a position ~2 tiles away instead; walking speed ~9 tiles/s; long unarmed routes through unmapped territory can be fatal where enemies exist. `TARGET_MISSING` when the target dies or changes surface. [README][live]
- `teleport` defaults `surface` to the actor's current surface and only moves a player-controlled character across surfaces (the engine teleports players, cars and spidertrons); a detached character is rejected. `repair` spends 600 HP per normal pack (durability 300 x repair speed 2); `shoot` reports rounds fired and force. [README]
- The managed server is headless: `screenshot` needs a connected graphical client (`just observe`) and a matching `script-output` directory. [README]
- `characterSpawn` workers persist in the save and are never cleaned up automatically; drain their inventories to a chest and retire them with `characterDelete(input:{character,force})`, which refuses player-owned or nonempty characters. `characterReturn` only works for characters created by `characterCreate` via a disconnected player. [README]

## 7. Rocket facts (Space Age 2.0.77)

- `rocket-part`: 1 processing-unit + 1 low-density-structure + 1 rocket-fuel, 3 s, category `rocket-building` [live recipe]. A launch needs **50 rocket parts** (`rocketParts 50`, status `waiting_to_launch_rocket`); not 100/1000. [memory; confirm with `inspect.settings.rocketSilo` when a silo exists]
- `rocket-silo` item recipe: 1000 steel + 1000 concrete + 200 processing-unit + 200 electric-engine-unit + 100 pipe, 30 s [live recipe].
- A cargo pod resting on a loaded silo is the **pre-launch** pod, not evidence of a launch. Sample position twice and check surfaces. [memory]
- `launchRocket` exists; stop on refusal and capture the engine reason. Mutation success alone does not prove a launch.

## 8. Tool-chain gotchas

- gqlcli needs CWD = repo root (`.gqlcli.json`) or `--url`; otherwise `404 page not found`. [live]
- `gqlcli script` default strict mode throws on any GraphQL error and loses the envelope; use `--strict=false` for mutation scripts. [live]
- gqlcli `script` has no `--jq` or `--format`; `-f` on `script` means `--file` (not format). `query`/`mutation` have `--jq`/`-f` output formats, but `--input` exists only on `mutation`; for a query use `--variables`. [live]
- Piping gqlcli's default toon output to external `jq` fails with `failed to parse: value expected`; pass `-f json` or use gqlcli's built-in `--jq`. Do not redirect stderr into the JSON output file. [live]
- Older `serve` builds reject `remove`/`mine`/`beltTake` through `EntityRefInput` with `flag provided but not defined: -surface` because the default `surface` is flattened into a backend flag. The working tree defines the flag and `TestCommandFlagsAcceptEntityRef` covers it; until `serve` is rebuilt, use `removeMany`/`placeMany` or the position form. [live][source fix]
- A rebuilt serve binary needs `gqlcli schema refresh`; the cache lives 10 minutes. [skill]

## 9. Build API mechanics (verified 2026-11-06 building the green-science cell)

- **The belt mutation is named `placeBelts` on this build** (`input: BeltRunInput`), not `placeBelt`; `placePipe` still exists separately. If a document fails with `Cannot query field "placeBelt" on type "Mutation"` another agent renamed or re-shaped it — re-introspect `Mutation` rather than assuming the skill is right.
- **`buildCell` entries take exactly one of `place`, `connection`, `recipe`** ("entry 0 (refinery) must set exactly one of place, connection or recipe"): emit a PLACE entry, then a separate RECIPE entry whose `recipe.ref` names the earlier place ref. `connection` entries take `from`/`to` POSITIONS only (no entity refs), and preflight refuses the whole cell on a missing placement item, so a dryRun first costs nothing.
- **An inserter tile must be orthogonally adjacent to BOTH source and destination; a 2-tile gap needs a belt between two arms.** Placing the arm one tile off (e.g. chest at y=51, machine top row y=53, arm at y=51) drops into empty space and the machine reads `item_ingredient_shortage` forever — read the arm's `inspect.dropPosition`/`pickupPosition` instead of assuming.
- **A run places every tile facing along the run, including its last tile**, so ending a run at a corner leaves that tile facing the old direction and the lane dead-ends there. Example: an eastbound run 10..18 followed by a northbound column at x=18 needed `setDirection` 0 on the last east tile. Check the corner tile's `direction` (or `beltTiles`) after placing any L-shaped route.
- **`configureInfinityContainer` fluidFilters is broken on this build** (P1 ticket): any non-empty `fluidFilters` on an infinity-pipe returns `server Lua: ... unexpected symbol near 'local'`. `filters:[]` plus a non-empty `fluidFilters` is required by validation, so there is currently NO way to create a sandbox fluid source through the API — crude oil/water cannot be supplied, which blocks plastic-bar, sulfur and chemical science. Item filters on infinity-chests work fine.
- **`placeMany`/`place` refuse `transport-belt`**: "must be placed with placeBelts(...), which routes the run and can tunnel under crossings". Underground belts still go through `place` using `undergroundType:INPUT|OUTPUT`.
- **`routing:ASTAR` takes `bend:AUTO` only** (a non-AUTO bend is rejected: "bend applies to DIRECT routing only"; it picks corners itself; was factorio-ai-player-r14). Underground spans are priced 1.05 per covered tile, so open ground stays a line of belts and a tunnel appears only where the surface is blocked. A goal tile fed by a foreign belt now fails at once as `BELT_ADJACENCY` naming the feeder (was `EXPANSION_LIMIT`/`NO_PATH`, factorio-ai-player-cc3); pass `allowBeltAdjacency:true` to merge. For exact L bends and loops use `routing:DIRECT` with `bend:HORIZONTAL_FIRST|VERTICAL_FIRST`. A refused run is `possible:false` with `conflicts[]` — read `possible`/`stopReason`, never just `errors`. A `serve` started before this change still has the old behaviour; restart the API (`just graphql-restart`).
- **A single-tile `placeBelts`/`connectEntities` run that abuts a perpendicular belt is REFUSED silently unless `allowBeltAdjacency:true`**: `from`=`to` + `direction` returned `placed:0, failed:0, conflicts:[]` — no error at all. A 3-tile straight run touching a side belt does report `conflicts:[{kind:BELT_ADJACENCY, message:"existing belt at ... feeds into this tile; pass allowBeltAdjacency to merge"}]`. Always read `placed`/`conflicts`, never just `errors`, and pass `allowBeltAdjacency:true` when merging into an existing lane.
- **A belt only emits into the tile it FACES.** A corner must be the tile that faces the new direction; the incoming straight belt side-loads into it. Placing the last belt of a straight run facing the old direction leaves the lane dead (cost me a silent 20-tile dry lane).
- `placeBelts`/`connectEntities` `from`/`to` for a run are inclusive endpoints and both ends get a belt; `direction` is only accepted (and required) when `from == to`.
- Result shapes: `placeMany → {placed,failed,entities[{unitNumber,name,position,direction}],errors[{code,index,message,target}]}`; `placeBelts`/`connectEntities`/`placePipe` → `{placed,failed,skipped,possible,stopReason,conflicts,errors}`; `place → ActionResult{unitNumber,entity,item,position,pairedUnitNumber}`; `transfer → {moved,tick,...,available,inserted}`.
- **`gqlcli mutation` needs an explicit `mutation { ... }` operation.** A bare `{ ... }` document is a query shorthand and fails with `Cannot query field "X" on type "Query"`. The file flag is `--mutation-file` (`--file` is rejected: "mutation is required"). Alias many mutations in one document — they run sequentially in one round trip.
- **Build supply**: `configureInfinityContainer` is the sanctioned item source. Its **output filter field is `name`, not `item`** (`InfinityContainerFilter{name,count,mode,quality}`), and `removeUnfilteredItems:true` keeps an existing void chest voiding while it also supplies. `transfer(input:{target:{unitNumber},item,count,inventory:CHEST,direction:TO_ACTOR})` moves them to a character. Neither is a machine *input* chest, so it stays inside the no-chest-fed-production rule.
- **Belt contents are not in `inspectMany`**: a belt's `inventories` come back empty. Read lanes with `beltTiles`/`beltStretch` (`lanes[].items`, `mixed`) instead.
- **Power is the silent killer of new cells**: a substation's supply area is 18x18 centred on it, so a cell one row outside coverage gets `no_power` (status 54) on every new inserter while machines look fine. Place a substation or pole before diagnosing "not moving"; a new substation auto-wires to any pole within wire reach (18 for substations).
- `probePlacement` `position` values in `blockedTiles` are the **centre** of a hypothetical entity and list the blockers that footprint overlaps, so `mode:GRID` rows encode footprints of the placed prototype, not free tiles. Verify free space with `occupancy`/`entities` and place, or probe a small area you already scoped.
- `setDirection` on a belt works when the direction is a multiple of 4 and reports `turns` (0 = direct write accepted); use it to fix a mis-faced corner instead of deconstructing.
